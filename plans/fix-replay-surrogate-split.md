# fix(replay): 切り詰めがサロゲートペアを割る（#1639）

Issue: #1639 / Branch: `fix/1639-replay-surrogate-split`

## User Prompt

> バグは潰す。

（#1634 の調査報告に添えた「サロゲートペアが守られていない」という指摘に対して）

## 症状（実測）

```
appendBoundedOutput('AB𠮟CD', '', 3)  ->  "\udf9fCD"  ->  �CD
```

再アタッチで復元されるスクロールバックの先頭 1 文字が `�` になる。

## 原因

`appendBoundedOutput` の切り詰めは **エスケープシーケンスの分割は守るが、サロゲートペアは守らない**。
`slice` は UTF-16 コードユニット単位なので、`cutAt` がペアの間に落ちると下位サロゲートだけが残る。

JS 文字列として不正ではないため、どこもエラーにしない。`JSON.stringify` は `"\udf9f"` として通し、
ブラウザで `�` として初めて見える — **誰も落ちないまま画面だけ壊れる**類。

## 直し方

`cutAt` を決める時点で、孤児になった下位サロゲートを 1 コードユニット読み飛ばす。
エスケープ走査（`splitSequenceLength`）より**前**に位置を確定させるので、既存のガードと素直に両立する。

先行するコードユニットが上位サロゲートかどうかは見ない。整形式の文字列なら自明であり、
入力が既に壊れていた場合も「孤児を落とす」が正しい答えなので、条件を増やす意味がない。

## テスト

- ペアの間で切ったとき、孤児が残らない（＝結果が整形式である）
- ペアが**丸ごと残る**位置で切ったときは、文字が保たれる（読み飛ばしすぎない）
- 既存のエスケープシーケンス保護が壊れていない（回帰）

break-verify: ガードを外すと新しいテストが落ちることを確認する。

## 対象外

#1634（日本語がアンダーバーになる）とは無関係。あちらは非 BMP でもリプレイ経路でもない。
